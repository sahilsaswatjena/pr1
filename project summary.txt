In entity package we are creating all database tables like doctor, area, city, state, we mapped the other tables to doctor table as bi-directional relationship. so the searching will be easier(website-PRACTO.com). "doctor" has many-to-one relationship with area table. so the foreign key will be located in doctor, and the primary key will be located in area table. The Doctor entity is the main part of the Doctor Service and holds all important details about a doctor, such as their name, specialization, qualification, contact number, experience, address, and profile image URL. Each doctor also belongs to a specific State, City, and Area, which are connected using @ManyToOne relationships because many doctors can share the same location. The Doctor entity is also linked to the doctor’s availability through a one-to-many relationship with DoctorAppointmentSchedule, meaning one doctor can have multiple schedules for different dates. Each schedule is connected back to the same doctor, so to avoid infinite looping during JSON conversion, @JsonManagedReference is used on the Doctor side and @JsonBackReference on the schedule side.
Every DoctorAppointmentSchedule contains multiple TimeSlots, which represent the exact times when the doctor is available for appointments. This forms a clean and understandable hierarchy: Doctor → Schedules → TimeSlots. Time slots also follow the same managed/back reference pattern to prevent recursion. This overall design makes it easy to store, navigate, and fetch a doctor’s complete availability structure. The Doctor Service itself runs as a Eureka Client, meaning it automatically registers with the Eureka Server, allowing other microservices to discover it dynamically without using fixed IP addresses or URLs. This creates a clean, maintainable, and scalable microservices-based architecture.
Then we are creating a controller layer to to retrieve the data from the database through Spring JPA Repository by GET Mapping. We are using the Doctor Repository to use it's inbuilt method like findall(), findByAll(). Then we are using the DTO layer to decide what data we want to show to the client in the API response.
